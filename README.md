# Bailey Hall evacuation laboratory

A clean TypeScript implementation of the supplied Bailey Hall mathematical model, with a React/Vite interface and a shared deterministic headless engine. Developed only on `rebuild-from-scratch`; no former simulator source is used.

## Run locally

Requires Node.js 22 or newer and npm.

```sh
npm ci
npm run dev
```

Open the local URL printed by Vite. The interface includes both floors, individual occupants, queue and occupancy colors, stepped-cross-aisle highlighting, geometry provenance, an inspector, public guidance, configurable interventions, and paired experiments in a background worker. Play speed changes animation scheduling, not the integration interval. Configuration changes validate and reset the run. Save a scenario and its seed to replay it.

```sh
npm run typecheck
npm test
npm run build
npm run test:browser
```

Browser tests use installed Chrome on macOS. On another machine set `CHROME_PATH` to your Chrome/Chromium executable. Playwright launches its own local Vite server. Tests do not require an external service or any original simulator.

## Reproducible experiments

```sh
npm run simulate -- --config scenarios/emergency.json --seed 101 --out results/run.json
npm run batch -- --config scenarios/emergency.json --seed 101 --runs 3 --out results/batch.json
npm run batch -- --config scenarios/emergency.json --compare scenarios/concert.json --seed 101 --runs 3 --out results/paired.json
npm run experiments -- --seed 101 --runs 3
```

The batch sequence is exactly `seed, seed+1, …`. `experiments` writes all named configurations, three-seed comparisons when invoked as above, and the 0.0125-second refinement of the first emergency seed. Optional `--jobs 4` runs independent policies concurrently without changing their random streams. Run files include the full configuration, seed, engine version, events, exit use, queues, density metrics, accessible progress, and sampled trajectories of aggregate clearance. The experiment sweep omits per-person logs from individual scenario aggregate files to keep them manageable; a single-seed CLI replay regenerates those logs. The refinement file retains both full event logs.

Large result files are versioned as lossless `.json.gz` archives; plain JSON remains available in this workspace and is regenerated by the commands above. Use `gunzip -k results/refinement.json.gz` in a fresh checkout to inspect a full archived log. `npm run archive-results` checks byte-exact round trips and writes a SHA-256 manifest of the source and results. `npm run report` can read either plain or compressed results.

`results/experiments.json` and [the validation report](docs/validation.md) contain the actual evaluated outcomes. A 900-second unfinished run has `clearance: null`, `status: "unresolved"`, and `clearanceBound: "T > 900 s"`. It counts against the 180-second success fraction. An unconditional mean is not reported when any replication is censored. Completed-only quantiles and means are explicitly labelled. Three replications are a smoke-sized exploratory sample, not evidence of operational reliability.

## Model and source hierarchy

The mathematical authority is [the LaTeX specification](docs/model/Bailey_Hall_Model_Final_Defensible.tex). The accompanying PDF, seven-page problem statement, both seating diagrams, and all six reference images were reviewed before implementation. The paper is unchanged.

The engine represents exactly 1,329 audience members: 527 orchestra, 486 mezzanine including three wheelchair places, and 316 balcony. It includes separate recognition and response, adjacent companions, persistent tastes and compliance, finite storage, lane FIFO and service credits, counterflow, locally visible gate delays, manager hearing, static/dynamic signs, projected barrier detours, and two scarce assistance teams. Exterior crossing and street arrival are separate endpoints.

Geometry is a **plan-derived network reconstruction**, not a surveyed CAD model. The drawings establish topology; metric widths, elevations, lane continuity, individual row counts, and wheelchair positions still require venue confirmation. Section totals are exact, but the small seat labels are not transcribed into an authoritative seat inventory. A geometry register exposes every metric assumption, and scenario JSON supports dimension overrides. See [implementation decisions](docs/implementation-decisions.md) for conventions and limitations, including finite-lane return feasibility and external street-time estimates.

The map renders the same graph that the engine traverses. Rows are restricted to their own occupants. The middle stepped connectors lie in an explicit break between orchestra rows and cannot be used by wheelchair users. The emergency elevator, backstage population, and ground-level population are excluded as specified.

## Code map

| Module | Responsibility |
| --- | --- |
| `src/engine/geometry.ts` | Plan-derived geometry, walls, columns, barrier detours, connectivity validation |
| `population.ts`, `rng.ts` | Named streams, audience traits, adjacent groups, fixed preferences |
| `transport.ts` | Gate/headway rates, finite storage, shared continuous lanes, credit accounting |
| `perception.ts`, `routing.ts` | Sightlines, feasible paths, visible gate delays, persistent utilities |
| `guidance.ts` | Public messages, hearing, acceptance, patrols, delayed reports |
| `simulation.ts`, `scheduler.ts` | Fixed-step event ordering, atomic transfers, invariant checks |
| `assistance.ts`, `metrics.ts` | Scarce assistance, separate endpoints, censoring and paired summaries |
| `src/ui/` | React map/controls/inspectors and browser batch worker |
| `scripts/` | Headless runs, paired batches, scenario sweep |
| `tests/` | Unit, full-engine, numerical, reproducibility, and browser tests |

No parameters are adjusted to make the 180-second objective pass. Predictions are conditional on this reconstruction and its uncalibrated assumptions; they are not a fire-safety or building-code certification.
